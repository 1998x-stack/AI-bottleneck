# Web UI 深度设计 / Design System v1

## 目标用户与核心操作
- **研究者**：发现领域最严重的系统问题，查看对应证据并阅读原报告。
- **工程负责人**：通过问题卡片找到可集成技术、风险、局限和验收指标。
- **产品/投资研究人员**：区分技术成熟度、商业价值及资料可信边界。
- **贡献者**：按数据契约补充新行业、新来源、新实验，不需要修改页面。

## 视觉语言
- 研究型 B2B 编辑审美：深青海军蓝 `#0b1f2d`、薄荷青 `#a5dfce`、白色 `#fff`、浅灰 `#f7f8fa`。
- 英文标签使用 `IBM Plex Mono`，数字统计用等宽字体；中文使用 Noto Sans SC 回退系统字体。
- 页面以「宽幅叙事 Hero + 左侧研究导航 + 右侧工作内容」构成。
- 问题优先级为唯一强语义色：P0 珊瑚、P1 琥珀、P2 蓝色；成熟度为中性标签。
- 大数字只展示从 catalog 实际读取的计数；规划行业绝不合并进已研究统计。
- 响应式断点 1180、860、540；低于 860px 隐藏侧边栏，主要工作区占满宽度。
- 用户可切换暗色模式，优先保留系统主题；减少动效时遵循 reduced-motion。

## 信息层次
1. Landing：面向跨行业的价值主张与知识库规模。
2. Overview：当前领域的高优先级问题和研究档案。
3. Issue Atlas：全量可检索索引；复合筛选 + 排序。
4. Detail Drawer：从问题切换到解决方案和验收指标，避免导航中断。
5. Report Reader：Markdown 原始报告完整展现，目录锚点可跳转；下载 MD 和 Word。
6. Evidence：来源登记，按类型筛选，支持跳转官方出处。
7. Methodology：研究方法与成熟度声明。

## 交互设计
- 全局键盘搜索 `/` 和 `Ctrl/Cmd+K`；Esc 关闭 overlay。
- 筛选关键词覆盖根因、症状、工具和方案名称。
- Issue 有稳定 URL 参数 `?view=issues&issue=DR-01`，适合分享和引用。
- 阅读器使用 `?view=reports&report=...` 与页面内目录锚点。
- 表格横向滚动；点击靶区域至少足够阅读和操作。
- 支持基于现有数据新增领域；未来再支持跨行业对比矩阵与关联检索。

## 验收
- PC 1440px、平板 768px、手机 390px，无横向页面滚动。
- 原始 Markdown 目录、表格、代码块、外链可读。
- 任一 Issue 均显示对应源编号，来源均指向明确 HTTPS 地址。
- 数据加载失败有错误界面；无数据时有空状态。
- 主题切换后内容仍有对比度；键盘能操作导航和核心检索。

## AI Music 的交互与可扩展性验收

音乐为第三个领域，与短剧、企业知识库共享总览领域卡、侧栏切换、Issue 过滤、来源检索、报告阅读、Word/PDF 下载。
详情视图对 `sop` 执行增量渲染，不要求旧领域数据包含该字段；最新报告按钮使用本领域 reports 最后一份，不写死其他领域的 report ID。
推荐深链：`?domain=ai-music&view=issues&issue=MU-01` 和 `?domain=ai-music&view=reports&report=ai-music-solutions-v2`。
新增领域只需内容 JSON、参考来源和 Markdown，沿用当前 UI 组件与 CI 文档导出体系。
