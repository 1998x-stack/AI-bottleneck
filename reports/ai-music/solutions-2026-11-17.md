# AI 音乐生产：核心 Issues 与瓶颈深度研究

**研究基准日：2026 年 11 月 17 日｜更新版本：v2.0（解决方案扩展版）**  
**覆盖范围：** 歌曲/纯音乐生成、中文歌词与演唱、多轨编辑、音频 QA、模型与 API、授权与发行、规模化工作流。  
**文档用途：** 技术调研、产品 PRD 输入、P0/P1/P2 项目规划、自动化 Agent 验收标准；新增20项逐项解决方案、技术选型、测试方案、失败回退和可复用数据契约。  
**判断性质：** “严重度”代表业务影响；“高频”仅在有可核验数据时作事实判断。未找到具有可比口径的跨模型故障发生率数据库。

## 执行摘要

**核心结论：最大的工程瓶颈不是从文本生成一首歌，而是将它变成可精确编辑、可复现、可审计、可授权、可稳定交付的音乐资产。**

目前有三条相互耦合的制约链：

1. **生成控制链（模型层）**：长程结构一致性 → 音符、段落、配器的细粒度控制 → 编辑后未修改区域的保真 → 演唱与歌词准确性。
2. **工业交付链（工程层）**：可下载的音轨/工程素材 → 自动质量诊断 → 分层返工 → 版本管理 → 人工听评 → 导出适配。
3. **商业权利链（产业层）**：训练/输入/声线/输出/录音/词曲权利链 → 平台具体准入规则 → 标注与元数据 → 真实受众与收入。

## 1. “最大”与“最多”必须区分

- **最严重（最大）**：造成不能合法发布、关键需求无法满足、成品损失不可恢复、商业客户无法验收的故障。应优先设为 P0。
- **最常见（最多）**：需要同一基准集、相同定义、相同模型版本与重复采样才能量化。公开资料没有足够的跨厂商、跨语种、跨任务的真实失败事件分母。因此本报告不会编造行业统一故障率排行榜。
- **影响最大但不一定频繁**：例如未经授权的声线使用、训练数据纠纷、平台拒绝上架；单次后果可能远大于多次轻度节奏漂移。
- **较常见但可局部修复**：例如节拍偏移、中文歌词咬字、stems 串音、参数不稳定；实际频率要在自有样本集测量。

### 本研究采用的 P0 / P1 / P2 判定

| 级别 | 判定原则 | 建议的 Gate |
|---|---|---|
| **P0 / 阻断发布** | 权利不明、无法导出、不可接受的人声/结构缺陷、重要修改不能实现、客户需求不满足 | 禁止自动发布；要求更换路径或人工批准 |
| **P1 / 阻断规模化** | 音轨质量、模型可替换性、自动 QA、任务可靠性、中文性能、成本失控 | 每批次必须有可观测指标和回滚能力 |
| **P2 / 形成竞争优势** | 风格资产库、动态配乐、个性化、实时互动、偏好学习 | 在 P0/P1 可控后进行增量实验 |

## 3. P0 问题深度剖析

### MUS-001 精确编辑与内容保留：最关键的模型瓶颈

**故障例子**：一首歌曲 1:10–1:16 的歌词需要替换，预期其他部分的人声、鼓和和声不变；实际重新生成后，附近和弦、音色、节奏、甚至整首的主唱声线均发生变化。

**原因树**：端到端潜空间表示缺少显式独立音轨；文本条件只在粗粒度控制声音；局部 inpainting 的边界上下文和节拍难以保持；重生成通常不具备位级或感知级不变性约束。SMEBench 把目标编辑与原始内容保留拆开评估，恰恰说明二者不能混为一谈 [S05]。

**现在怎么解决**：优先在 MIDI/乐谱层修改旋律及和弦；拥有源 stems 时只重做受影响音轨；使用局部 inpainting 的模型；在返工时采用固定节拍网格、音色参考和 crossfade；对编辑窗口外设差分检查和人工 ABX 听评。

**仍未解决**：精确的“只改一处、其他地方完全不变”尚非跨模型通用保证；编辑音乐内容和保留演唱/录音身份之间经常存在取舍。

**验收指标**：`edit_success_rate`（目标改动成功）与 `preservation_pass_rate`（编辑区外未发生不可接受变化）分开测；报告每个时间窗口的失败案例；禁止只用整体 CLAP 相似度证明局部保真。

### MUS-002 长曲结构一致性与音乐性

**症状**：开头漂亮，主歌、预副歌、副歌或桥段之间缺乏因果；重复片段不合理、动机未发展；4 分钟歌曲的末段突然弱化或飘离主题。

**根因**：短时纹理与长时结构的学习目标不一致；模型需要同时处理约 50ms 音符起点和数分钟的主题、和声、段落依赖；暴露偏差与重复采样引发结构漂移 [S03]。

**缓解**：先创建 `song_form.json` 和小节级结构图；制定主题、和弦、速度变化计划；分段生成前后做桥接、主题动机复现和人耳听审；必要时用符号级工作流重建，而不是盲目增加 Prompt 长度。

**验收**：人工结构评分；段落边界检测 + 和声变化分析；“再现主题是否可识别”的盲听问卷；不能只比较整首 embeddings。

### MUS-003 语义提示词与硬音乐约束之间的距离

**症状**：“82 BPM / A 小调 / 4/4 / 不要吉他 / 第 32 小节进入副歌”只满足一部分；改一个要求会破坏其他要求。

**根因**：自然语言作为弱条件，不是确定性数字音频工作站指令；模型内的节拍、音色、乐器概念可能耦合 [S03]。

**缓解**：把要求分成“硬约束”和“软偏好”；硬约束进入 MIDI、节拍地图和后处理；以偏差测试（BPM MAE、段落时点误差、乐器存在判别）自动反馈；不满足则路由到不同模型或人工编辑。

**验收**：每个硬约束单独 `passed/failed/not_measurable`；对自动检测器采用人工校准样本，避免把节拍估算当真值。

### MUS-004 中文演唱、人声一致性与歌词对齐

**症状**：中文词漏字、句尾拖音压缩发音、含混齿音、人物声线在不同段落改变；合声与主唱串扰。

**根因**：字/音节/音素与音高、时值的映射不稳定；歌唱拉伸造成普通 ASR 性能下降；训练语种与曲风覆盖不均。2026 年 ISMIR 论文指出，缺少显式语言信息的控制方法不能保证歌词准确，表现为较高的音素错误率 [S06]。

**缓解**：歌词分句 + 拼音/音素 + 音符时值级强制对齐；难字、儿化、轻声、人名设词典；关键句保留真人演唱选项；多次生成后由中文母语听审；ASR 仅作为筛查而非最终裁决。

**验收**：`CER/PER`（需注明使用何 ASR/转写标准）、关键词可懂度、跨段声线稳定性人工评分、歌词切分与换气审查。

### MUS-005 自动评分不能代替音乐判断

**症状**：FAD/文本音频相似度高，但用户认为“没有高潮、机械、唱不清”；一项综合分掩盖人声或编曲短板。

**根因**：单项客观指标反映统计分布、语义关联或局部音频质量，不必然反映音乐性。2026 年综述指出评估标准仍碎片化；SongBench 提供七维专业评价，并使用 11,717 个专家标注样本 [S03][S04]。

**缓解**：三道闸门——L1 音频技术无故障；L2 结构、歌词、配器和场景一致；L3 专家与真实用户盲听；给每个维度保留独立评分、失败原因及修正建议。

**验收**：自动评估与人工评分的相关性、召回率及误报率；对关键 P0 缺陷重点优化漏检率；采用双盲 A/B 而非单轮主观评分。

### MUS-006 商用权利链和作品资格不是一回事

**风险例子**：某 AI 平台声称订阅期间可商业使用，但发行商要求训练数据来源满足额外规范，或词曲出版业务要求能够识别具备充分人类创作的词曲作者。

**已知政策差异**：Suno 付费下载作品可获得相应商业使用权，但明确不保证版权保护 [S14]；美国版权局 2025 年说明人类必须贡献充分的原创表达，单纯提示词不足 [S13]；TuneCore 仅接受其认定使用充分授权训练数据模型的 GenAI 音乐，并对出版管理另有人类作者要求 [S12][S19]。

**缓解**：把 `model_license`、`input_license`、`voice_consent`、`human_authorship`、`release_channel_rules` 分离存储；发布前出具权利检查清单；所有权利缺失不可自动推测为通过。

**验收**：每个输出必须有来源、授权凭证、生成日期、人工贡献记录、终端用途和可下载记录。法律合规需要按目标司法辖区及具体合同复核，不能由模型分数作结论。

### MUS-007 渠道策略与产物导出限制

**现实情况**：Udio 帮助中心 2026-02-17 明示音频、视频及 stems 下载被关闭 [S08]；Suno 2026-11-13 帮助文档规定 Pro 每月 20 次下载、Premier 60 次、免费用户 0 次；Studio 工作流不受该下载额度约束 [S09]。Bandcamp 禁止全部或主要部分由 AI 生成的音乐和音频 [S15]；TuneCore 仅接受符合其训练数据授权框架的 AI 模型作品 [S12]；DistroKid 允许合规 AI 音乐，但强调完全的合法分发权、不得冒名及批量垃圾内容 [S16]。

**结果**：不能将“能生成”推导为“能导出”，也不能将“能下载”推导为“可通过任意分销渠道上架”。

**缓解**：渠道 × 模型 × 商用权益 × 文件导出格式建立四维策略矩阵；每月自动复核官方政策；设计多 Provider 备选和跨模型业务降级；同一内容不应盲目重复上传。

**验收**：每次发布生成带时间戳的可用性快照，无法满足导出许可即阻断交付。

### MUS-008 参考音频、采样、相似性与声线克隆

**风险链条**：未经授权的参考录音 → 声音克隆或局部模仿 → 相似性投诉 → 下架、纠纷、客户交付失败。训练许可、参考录音许可、声音肖像或人格权、最终输出权利是独立议题 [S13][S17]。

**缓解**：声线使用必须记录明确、可核验的授权与用途范围；默认禁止模仿具体真实歌手/声音身份；外部样本要求来源证明；相似性检测作为“人工复核触发器”而非侵权自动裁判。

**验收**：缺乏声线授权的资产不能进入 commercial_release；对高相似性作品执行人工法律与音乐专业审查。

## 4. P1 问题及针对性工程解法

### MUS-009 分轨提取质量不可逆

仅拿到最终立体声母带后，再通过分离模型抽取人声/鼓/贝斯，通常不可期待得到与原始录音工程等价的独立轨道。可出现串音（bleed）、缺失（missing target）和相位/频谱伪影。2026 年 MVSep 质量评价研究针对 bleed 和 fullness 给出专门指标 [S07]，AES 2026 的研究亦强调源分离主观感知与客观 SDR/FAD 之间存在评价问题 [S18]。

**处理**：首选原生多轨输出；不得已时采用双模型分离 + 小样本试听；分离质量低时允许替换轨道或重编配。对人声、打击乐及混响尾音分别检测。导出前听完整曲，不只听单轨静态样本。

### MUS-010 节拍和时间轴漂移

Suno Studio 2.0 官方承认新生成段落可能位于节拍前后，建议打开节拍器检查 [S10]。因此新增轨道“风格一致”不代表“时间戳准确”。

**处理**：生成后执行 transient/onset 检测、节拍网格对齐、音轨起点偏移计算；不能无条件拉伸整段，避免破坏鼓音色或人声。保存 `audio_offset_ms` 和 `stretch_ratio`，必要时在 DAW 审核。

### MUS-011 混音与母带治标不治本

EQ、压缩、响度归一化可以调整整体声学呈现，不能还原生成过程中已缺失的发音、被混在一起的乐器，亦不保证消除非线性失真。

**处理**：先判定问题所在层：声源生成 / 音轨提取 / 编曲 / 混音 / 母带。把根因转交给对应操作；严重内容缺陷应重生成或重编曲，不应无限叠加效果器。

### MUS-012 中文歌词与 ASR 评价偏差

以普通语音 ASR 计算歌唱字符错误率，会同时测到“合成咬字错误”和“ASR 对歌唱语音不适配”的影响。应选用适合歌声的转写方法、母语听评和句级对齐，特别检查多音字、英文混唱、快速 Rap、延长元音和儿化。

### MUS-013 第三方 API 稳定性与供应商锁定

接口能力、时长限制、输出 stem、商业权利可能随时改变；Udio 与 Suno 的 2026 年下载条款变化已提供现实案例 [S08][S09]。

**处理**：Provider Adapter 不直接暴露平台参数；维护 capability contract（是否支持纯音、中文、WAV、stems、API 下载、编辑等）；每次任务保存模型版本与参数；通过 canary 测试监测策略漂移。

### MUS-014 显存、性能、批处理与可靠性

ACE-Step 1.5 官方部署文档针对不同显存档位给出量化、CPU offload、并发及最大长度调整；低显存部署可能牺牲吞吐并增大排队延迟 [S11]。

**处理**：任务状态机 + 幂等键 + retry/backoff + 资源配额；按预估音频时长和模型 VRAM 分配 GPU；缓存权重、分离与编码阶段；以“验收合格作品成本”而非单次推理时延衡量效率。

### MUS-015 版本与溯源缺失

如果没有 recording manifest，一首音乐只保存为 `song_final_v7.mp3`，未来就难以判断提示词、模型、人工修改、素材来源和商业授权。

**处理**：使用 `asset_id`、`parent_asset_id`、`model_version`、`prompt_hash`、`input_refs`、`license_snapshot`、`review_signoff`；把工作流视作音乐媒体资产管理，而非单次聊天文件生成。

### MUS-016 视频配乐时间锚点不可靠

视频要求“第 31 秒抬升，第 43 秒完成收束”时，普通文本音乐生成只能提供软指导。应先从镜头/旁白提取 cue sheet，再采用可编辑 MIDI、多段生成/拼接和速度匹配实现精确时间设计。

### MUS-017 相似性治理不能简单等同版权裁定

基于 audio fingerprint、旋律转写、和弦序列与音频 embedding 可以筛查高相似度，但不能仅凭一项相似度阈值裁定侵权；需要区分流行公式、公共领域元素、录音取样和受保护表达。

### MUS-018 内容过剩与发现机制失衡

Deezer 的上传量与收听份额反差，以及 Spotify 的推荐过滤表明，单靠批量上传难以保证被听见 [S01][S02]。对客户型产品，应优先考察真实交付、许可收入、再次采购；对直接面向听众的产品，应考察完整收听、主动搜索、收藏及复听，而非上传量。

## 5. P2 方向：不要太早优化的能力

1. **原创风格资产库**：建立可证明授权的自有素材、主题动机、乐器组合、品牌声音规范。
2. **面向场景的动态音乐**：按游戏状态、镜头节奏与用户互动调整和声、强弱和段落。
3. **多轮创作记忆**：记录用户对节奏、人声、旋律的反馈，不仅存储 Prompt。
4. **实时生成与协同**：对实时性高的场景先用预渲染分层混音和状态切换；生成式实时音频需要更严格的延迟、节拍连续性及许可证检验。

### MUS-001｜局部修改牵连未修改区域（P0）

**现有可行工具与证据：** 商业可用：Mureka `/v1/song/region-edit` 能指定毫秒窗口与新歌词，至少 3 秒编辑窗口，但并未承诺区域外波形不变 [S22]。Suno Studio 2.0 提供 MIDI、编辑与多轨环境 [S10]；Eleven Music v2.5 提供段落编排与局部修复 [S23]。研究/本地：YuE2 的符号规划和乐谱编辑适合音符级工作，但要按主体检查模型权重许可证 [S24]。

**路线选择与取舍：** A（首选、工程可编辑）：维护 MIDI/ABC 乐谱及原生 vocal/instrument stems；歌词仅变动时在歌声合成器重渲染该句，保留原伴奏。B（平台原位编辑）：调用 Mureka region-edit，保留完整原音频和版本散列。C（无法获得原始轨）：音乐源分离后对目标声部返工，最后混音拼接；这属于降级方案。

**落地 SOP：**

1. 先把修改目标写成 `edit_spec`：asset_id、时间起止、歌词/音符/配器目标、必须保持不变的区域和声部。
2. 优先选择符号级或单轨编辑；只有无法完成时才让模型重绘混合音频，固定受支持的 seed/参考音色/上下文。
3. 记录生成原文、时间窗口和候选；局部边界做短 crossfade，不把编辑外区域重新编码数遍。
4. 执行 A/B 区外差分、边界瞬态检测和盲听；不合格回滚原版并升级为人工 DAW 编辑。

**验收与数据采集：** 编辑成功率、未编辑区域保留通过率、边界爆音率、人工返工分钟/次；测试样例覆盖替换歌词、改音高、删除乐器、改变音量。

**残余风险与失败回退：** 分离后修复可能产生相位串音；生成平台的局部编辑可能同时重排和声。SMEBench 已将编辑达标和保留度分开评估，不能将文本相似度作为保真保证 [S05]。

### MUS-002｜长程结构漂移与缺乏发展（P0）

**现有可行工具与证据：** 现有方案分为结构化规划与分段生成：Eleven Music 的 composition plan、段落时长与分段编辑接口 [S23][S25]；Google Lyria 3.5 允许用时间标签、Verse/Chorus 等结构提示，但官方注明并非多轮编辑，时长不保证完全精确 [S26]；YuE2 可在乐谱层规划 [S24]。

**路线选择与取舍：** A：小节级 `form_map` + 人工/符号主题动机，优先固定和弦、主题、乐器进出场。B：按桥段和副歌分段生成并使用重复主题动机与共享音色参考。C：单次整曲生成后通过结构诊断筛选，只适用于质量阈值相对宽松的内容。

**落地 SOP：**

1. 把歌曲拆成 8/16 小节的音乐句，指定 A/B/A 主题复现、和声/能量曲线与乐器层次。
2. 建立段落边界、音调与节拍地图；生成候选前先人工审查结构提纲。
3. 对各段使用可兼容参考素材，保留段间节拍和混响尾音过渡；必要时重编 Bridge 而非整曲重做。
4. 用主题复现盲听、结构标注一致率、段落时长偏差验收；长曲单独抽样，不以短样本结论代替。

**验收与数据采集：** 段落到位率、主题动机复现正确率、长曲后半段专家评分、结构失败定位时间；至少覆盖 2/4/6 分钟三个区间。

**残余风险与失败回退：** 分段拼接易导致混响、歌手和响度不一致；歌词副歌重复并不等于音乐发展。综述将音乐性与长时一致性列为开放挑战 [S03]。

### MUS-003｜BPM、调性、和弦和配器等硬约束失效（P0）

**现有可行工具与证据：** Google Lyria 3.5 支持 BPM、乐器、结构、时间点等文本约束，但仍属于生成式控制而不是 DAW 强制校验 [S26]；ACE-Step 1.5 可在元数据中使用 BPM/Key/Time Signature 等信息，实际约束达成仍应复核 [S27]。Spotify Basic Pitch 能把相对干净的单乐器音频转 MIDI，复杂完整混音的误差更大 [S28]。

**路线选择与取舍：** 硬约束（精确 BPM/小节/持续时间/必需音符）落在 MIDI、节拍地图和编排脚本；软约束（氛围/风格/温暖程度）交给生成模型。规定「建议」与「强制」两个字段，避免 Prompt 文字强制需求发生隐性降级。

**落地 SOP：**

1. 在 SongSpec 中为每条要求记录 `hard|soft`、测量方法、容差、来源与优先级。
2. 优先生成 MIDI，选择乐器音源渲染；如果先生成波形，则先估算拍点、调性和段落。
3. 自动测量时长/节拍，人工确认复杂节奏、转调和目标乐器是否真正出现。
4. 条件不满足先局部 DAW 修复，再考虑重新生成；记录每项约束失败原因。

**验收与数据采集：** 约束满足率按字段单独统计；`|BPM_est-BPM_target|`、段落入点误差、禁用乐器误报/漏报、和弦识别人工一致率。

**残余风险与失败回退：** beat tracker 对切分节奏、无鼓/变速歌曲存在半拍/双倍误差；自动 key 判别对转调不可靠。无法精准测量时设 `manual_required`，不得自动判通过。

### MUS-004｜人声自然度、歌词准确性与声线一致性（P0）

**现有可行工具与证据：** Synthesizer V 2 Pro、ACE Studio 都支持音符/歌词驱动歌声与发音编辑；前者能调整音素长度、力量及字典，并于 2026-11-02 更新了音素与可重现渲染机制 [S29][S30]。ISMIR 2026 MPEcho 研究显示显式音素级条件有助降低歌词音素错误率，但该论文任务是翻唱而非一切歌声生成 [S06]。

**路线选择与取舍：** A：对商业主唱选择授权声库 + MIDI/歌词/音素编辑或真人补录；B：端到端歌声用于草稿及非关键段落；C：音频转 MIDI 作为反向工程，再由可控合成器重做。

**落地 SOP：**

1. 创建逐字歌词、拼音/音素、音符时值与演唱分句的对齐表；识别多音字、人名、Rap 与中英混唱。
2. 针对错误词句单独检查元音是否被过度拖长、辅音是否有足够前置时间。
3. 声线用经授权、固定版本的 Voice ID 或合成声库；相邻段落间验证一致性。
4. 中文母语审听至少覆盖全部副歌和每首随机抽取的主歌，关键唱段人工补录或改用合成器。

**验收与数据采集：** 逐句可懂度、人工逐字校对正确率、音素错误率 PER、唱段间音色一致性、异常呼吸/齿音缺陷率。

**残余风险与失败回退：** 普通语音识别器会把歌唱延音误判成漏字，WER/CER 是辅助检测而非唯一真值；更换声音不能解决音符时值不合理的问题。

### MUS-005｜自动质量评分与人耳偏好脱节（P0）

**现有可行工具与证据：** SongBench 以 Vocal、Instrument、Melody、Structure、Arrangement、Mixing、Musicality 七个维度评价，并包含 11,717 个专家标注样本 [S04]；SMEBench 指出使用不同编辑度量可能改变系统排名 [S05]。现有音频技术指标只能发现部分工程错误，无法直接证明艺术质量。

**路线选择与取舍：** 采用三层评分：信号健康（自动硬门禁）、结构/歌词/控制符合程度（模型+人工校准）、专业与目标用户盲听（决策）。保留维度分数和失败时间轴，不计算掩盖 P0 缺陷的唯一综合分。

**落地 SOP：**

1. 定义维度评分 Rubric：0-4 等级、可听示例和常见失败标签，先做 30 个标注一致性样本。
2. 每个候选先检测解码、静音、clipping、时长，再做音乐结构和人声诊断。
3. 至少三位不同背景听评者盲听，拆分技术缺陷、审美偏好与场景适配。
4. 每周对照专家结果校准自动模型阈值，记录误报/漏报和置信区间。

**验收与数据采集：** 各维度人工评分一致性、Spearman 相关、P0 缺陷召回率、平均听审成本、误判后客户投诉率。

**残余风险与失败回退：** 质量模型与用户群体可能有偏差；不同场景重视的维度不同，不能把流行歌曲评分模型直接用于游戏循环 BGM。

### MUS-006｜商用授权与著作权证据链不完整（P0）

**现有可行工具与证据：** Suno 官方明确区分付费生成歌曲商业使用权与版权资格 [S14]；美国版权局强调充分的人类原创表达，单纯提示词不足 [S13]；TuneCore 的发行框架要求模型训练素材充分授权，而其 Publishing 对作品要求有实质人类创作 [S12][S19]。C2PA 2.4 音乐规范提供制作来源声明机制，但明确不裁定法律权利 [S31]。

**路线选择与取舍：** 建立三重合规门禁：`model_and_terms`（模型/平台许可）、`input_and_voice`（歌词、样本、声线许可）、`output_and_channel`（成品权利、发行地域和渠道资格）。证据缺失状态为 UNKNOWN，不等于 PASS。

**落地 SOP：**

1. 在生成前保存账号方案、订单/许可、服务条款版本、模型权重许可、训练数据官方声明。
2. 给歌词、旋律、录音、封面、样本、声线分别分配 source_id 与权利主体。
3. 记录人工创作贡献（乐谱修订、歌词、编配决定、录音与制作日志），不要只是写“AI 辅助”。
4. 按发行渠道评估法域与发布规则；需要时交由专业法律人员复核，不自动给出版权所有保证。

**验收与数据采集：** 权利台账完整率、授权即将过期数量、渠道审查通过率、合规阻断是否可解释、外部素材凭据追溯成功率。

**残余风险与失败回退：** C2PA 签名保证可验证的声明来源，不保证声明真实或内容必然合法；商用许可未必等于作品有可登记版权。

### MUS-007｜发行渠道准入与生成/下载限制冲突（P0）

**现有可行工具与证据：** 官方政策存在直接差异：Udio 2026-02-17 禁用音频/视频/stems 下载 [S08]；Bandcamp 不允许全部或大部分由 AI 生成的音乐 [S15]；TuneCore 仅接受满足其训练数据许可要求的模型作品 [S12]；DistroKid 允许符合其权利、反冒名和反垃圾内容规则的 AI 作品 [S16]；YouTube 要求符合情形的 AI 音乐披露 [S32]。

**路线选择与取舍：** 生产路线不可绑定无法合法导出/下载的服务。建立 Provider × Model × Plan × Destination × Territory × UseCase 策略表，并将结果分成 ALLOW、REVIEW、BLOCK、UNKNOWN。

**落地 SOP：**

1. 项目创建时就选择交付场景与发行目的地，而非做完音乐才查政策。
2. 每条 Provider 集成做下载、授权与格式真实冒烟测试；本地保存获准下载的资产，绝不绕过技术/合同限制。
3. 上线前刷新政策快照，检测规则版本变更，阻断过期审批。
4. 若某渠道不允许，改为客户内部使用或合法替代渠道，不能冒名、洗稿或隐瞒 AI 标识规避规则。

**验收与数据采集：** 合规渠道覆盖率、导出成功率、政策变更发现时延、发行拒绝率和拒绝原因分布。

**残余风险与失败回退：** 对平台条款的解释不能脱离具体国家、合同和账号方案；二级分销商实际执行可能更严格，应允许人工确认。

### MUS-008｜未经许可的声线模仿、采样与参考音频风险（P0）

**现有可行工具与证据：** Mureka 提供 vocal-clone API，输入 15–30 秒声音样本即可创建声线 ID；技术存在不等于拥有被克隆者授权 [S33]。Eleven Music 的参考音频功能会做版权合规筛查 [S23]；DistroKid 明确禁止未经许可模仿他人声音、形象或身份 [S16]。

**路线选择与取舍：** 默认选择有明确商业声库许可的虚拟歌手，或本人/合作艺人签署范围清晰的授权。对于外部样本采取“先上传证据、后允许生成”的默认拒绝策略；相似度筛查只能触发审查，不能当作版权判决。

**落地 SOP：**

1. 上传样本时登记表演者姓名、授权文件、用途、地域、期限、可否二次训练/转授权及撤销程序。
2. 建立声线/参考音频白名单，使用访问控制与审批角色隔离。
3. 对真实歌手相关描述和高风险声音请求触发人工审查，生成日志保存经过但不公开样本隐私。
4. 发生权利投诉时冻结分发、保全凭据、提供删除/替换和纠纷处理路径。

**验收与数据采集：** 已授权声线覆盖率、无凭证请求阻断率、投诉响应时效、授权过期的复查率。

**残余风险与失败回退：** 音色听起来“不像某位歌手”并不能证明不存在人格或版权风险；声线与底层录音的权利应分别确认。

### MUS-009｜音源分离的串音、声源丢失与伪影（P1）

**现有可行工具与证据：** 优先使用生成器原生 stems；没有原生轨时，`python-audio-separator` 支持 MDX/MDXC/Demucs/VR 与多模型 ensemble，可批处理并导出多轨 [S34]。Mureka `/v1/song/stem` 官方支持多种分轨模型，部分提供 MIDI 输出，但它是提取后的估计而非原始 MIDI 工程 [S35]。

**路线选择与取舍：** A：原生多轨/直接乐器生成；B：不同模型的 vocal/instrument separation 对照；C：无法修复的声部重新录制或重新合成。分离模型不是“无损拆轨器”。

**落地 SOP：**

1. 把输入混音归一到明确采样率和声道，保存源 hash，避免因重采样导致后续误比较。
2. 针对任务单独选择两轨/四轨/多轨模型，输出 WAV；对长音频使用切片时检查边界。
3. 对每条 stem 听有声乐器的残留和目标音源的丢失；对重混结果做 ABX 和混音相容性测试。
4. 若 bleed/fullness 不合格，切换模型或替换目标 stem，不无限叠加降噪器。

**验收与数据采集：** bleed/fullness 听审分值、残留量、单轨频谱伪影、重混误差、分离成本/分钟。

**残余风险与失败回退：** 干净人声可能因过强抑制损失气声、尾音；多模型 ensemble 能减轻但不能证明恢复了真实原始声轨。

### MUS-010｜多轨时间轴、拍点与相位漂移（P1）

**现有可行工具与证据：** Suno Studio 2.0 官方承认新生成音轨可能略早或略晚于节拍，建议使用节拍器及独奏核对 [S10]。在专业 DAW 中可通过片段对齐、节拍网格、 transient 分析及局部拉伸处理。

**路线选择与取舍：** 使用统一样本时钟、tempo map、bar/beat/tick 和 timecode；先修 offset，再判断是否需要节奏局部量化或 time stretch；对相位相关的多麦/多 stem 不做独立随意拉伸。

**落地 SOP：**

1. 每轨保存 `start_sample`、`offset_ms`、`bpm`、`tempo_map_version`，不依赖肉眼拖动。
2. 使用节拍/瞬态估计生成候选偏移，遇到弱鼓、三连音或半拍歧义由人工确认。
3. 只对有明显错误的片段执行校正，渲染后检查相邻轨攻击时差和人声辅音边界。
4. 保留可逆的变速参数与原音频副本，未通过时回退并 DAW 微调。

**验收与数据采集：** onset 偏移分布、关键鼓点最大时差、相位相干异常、修正引入伪影次数。

**残余风险与失败回退：** 多轨不齐可能源自模型输出延迟，也可能是本来就有意的人性化节奏；不能一律量化到节拍网格。

### MUS-011｜混音和母带掩盖不了上游生成错误（P1）

**现有可行工具与证据：** Spotify Pedalboard 提供可脚本化的 EQ、压缩、限幅、混响及插件加载 [S36]；ITU-R BS.1770-5 是响度/True Peak 测量参考标准 [S37]，`pyloudnorm` 实现了较早的 BS.1770-4，应留意版本差异 [S38]。

**路线选择与取舍：** 把缺陷分为：内容缺陷（错词/旋律丢失）→ 回到生成；分轨缺陷（串音/相位）→ 分离与重录；混音缺陷（频段冲突/动态）→ EQ/压缩；母带缺陷（峰值/整体响度）→ limiter/适配。

**落地 SOP：**

1. 对音轨做动态分析与技术检查，区分故意失真和异常失真。
2. 使用最小效果链处理具体缺陷，而不是叠加“AI 一键修复”插件。
3. 按照实际交付场景设置响度/True Peak 目标，由客户或平台规范指定；不采用无来源的统一 -14 LUFS 强制标准。
4. 用多个播放设备审听；导出前比较处理前后的音色与动态，防止过度限制。

**验收与数据采集：** 响度范围、True Peak 超限率、削波/爆音事件、音质盲听通过率、源阶段返工占比。

**残余风险与失败回退：** 增强高频可能放大齿音；去齿/降噪可能损失表情。响度达标不是音乐质量达标。

### MUS-012｜中文歌唱转写、音素对齐和质量评估偏差（P1）

**现有可行工具与证据：** Synthesizer V 提供按音符歌词、音素编辑和自定义词典 [S29]；ACE Studio 提供 Vocal-to-MIDI 将声乐转为可编辑音符与歌词 [S39]；ISMIR 2026 MPEcho/Phonsa 将歌唱音素对齐作为专门任务，表明通用口语对齐不能直接替代 [S06]。

**路线选择与取舍：** 建立中文歌唱专用评估流程：原始歌词清洗→分句与汉字多音读法→声乐分离→歌唱 ASR/音素校正→人工逐句确认→错误 span 返工。

**落地 SOP：**

1. 为项目定义简繁字、儿化、多音字、拼音、英语夹杂、重复歌词的统一转写规范。
2. 先在有干净人声的素材上做音节对齐，再测试含伴奏素材；拒绝无依据的 10ms 精度承诺。
3. 建立发音黑名单/词典，对重点人名和品牌名称要求人工确认。
4. 按音乐风格（抒情、Rap、童声、和声）分别统计 CER、PER 与人耳可懂度。

**验收与数据采集：** 人工判定逐字正确率、自动 ASR CER/PER 及其偏差、强制对齐错误分钟数/首、误删歌词数。

**残余风险与失败回退：** 声母短且轻、拖腔长音、重叠合唱会导致 ASR 误判；被识别错误不总是合成质量错误。

### MUS-013｜API、计费或下载政策变化与供应商锁定（P1）

**现有可行工具与证据：** Udio 关闭下载与 Suno 在不同付费方案设置月度下载数量均说明“可访问网页”不代表“可持续导出” [S08][S09]。Mureka、Eleven Music 提供明确的 API，但各自能力、任务状态与价格不同 [S23][S40]。

**路线选择与取舍：** Provider Adapter 应记录能力，不只是包装 HTTP。统一 `generate/extend/edit/stem/status/cancel/download` 语义，并用独立能力矩阵表达 `supported|unsupported|unknown`。

**落地 SOP：**

1. 定义 Provider 接口、任务状态与导出契约；参数转换时丢失的信息必须告警。
2. 每天运行低成本 canary：创建短样本、等待、合法下载、解码、检查格式；监测变更及到期 URL。
3. 所有已获许可的中间文件立即归档到自有对象存储；凭据交由密钥管理，不写入日志。
4. 执行 429/5xx/超时模拟，带幂等键重试；切换模型前重新审核许可与结果一致性。

**验收与数据采集：** 接口可用率、合法下载成功率、能力漂移次数、平均恢复时间、供应商更换成本。

**残余风险与失败回退：** 不同模型的输出审美不可完全互换，供应商“技术可替换”不代表客户能无感迁移。

### MUS-014｜GPU 显存、模型吞吐和长任务恢复（P1）

**现有可行工具与证据：** ACE-Step 1.5 官方文档根据 ≤6GB、8–16GB、20GB 以上等显存档位选择模型、offload、INT8 及推理后端，提供 REST API、Python API 与 LoRA [S11][S27]。本地运行能降低服务锁定，但 GPU、工程维护和模型授权由使用者承担。

**路线选择与取舍：** 采用消息队列、GPU 资源池、不可变输入、幂等作业和可续跑状态机。对每个模型记录显存峰值、每分钟音频耗时、OOM 率和失败恢复时间。

**落地 SOP：**

1. 以模型权重大小、音频长度、批处理数量估算 VRAM，按 GPU tier 做作业路由。
2. 低显存优先减少 batch、启用已验证的量化/offload，降低吞吐预期。
3. 将推理、分轨、混音、编码分成不同队列，避免 GPU 任务被 IO 工作占用。
4. 对 OOM、进程终止、URL 过期做故障注入；每次完成一个阶段即写入对象存储和 checkpoint。

**验收与数据采集：** GPU 利用率、显存 P95、生成耗时 P50/P95、任务恢复率、每首合格成品的 GPU 分钟/费用。

**残余风险与失败回退：** 厂商宣称的高速度依赖特定硬件和采样设置；低显存/CPU offload 可能显著增加时延，应在目标机器实测。

### MUS-015｜Prompt/模型版本/音频资产不可追溯（P1）

**现有可行工具与证据：** C2PA 2.4 的音乐资产指导覆盖 AI 声明、创作动作、来源资产、制作贡献者和下游元数据，但强调其不裁定版权 [S31]。结合内容寻址资产和版本 DAG 可构建审计系统；可使用 c2patool 管理声明 [S41]。

**路线选择与取舍：** 每一次生成、编辑、分轨、混音、母带都产生不可变 `asset_id` 和 manifest；区分 source master、working stems、release masters，并可还原父子版本图。

**落地 SOP：**

1. 所有文件计算 SHA-256；manifest 中记录模型、参数、输入文件、种子（若支持）、代码版本、时间、人工操作与许可证快照。
2. 对象存储启用版本控制，发布版只允许引用通过质量和权利门禁的 asset_id。
3. 选择性给可支持的音频格式签署 C2PA；同时维护后端不可篡改审计日志。
4. 定期抽样重构某个发布作品的来源链，确认能够追溯到上游素材与审批。

**验收与数据采集：** 血缘追踪成功率、孤儿资产数、不可重现请求比率、授权证据关联率、生成版本归档延迟。

**残余风险与失败回退：** 相同 seed 不代表跨 GPU、版本或非确定性云服务能逐比特重现；应区分“参数可重放”与“输出可重现”。

### MUS-016｜视频配乐 cue 入点、情绪节点不准（P1）

**现有可行工具与证据：** Lyria 3.5 文档给出带时间范围的结构提示，但官方同时提示精确时长仍由生成结果决定且不支持多轮编辑 [S26]。精确影视配乐通常需要 DAW、MIDI、分段导出和画面 cue sheet，而非只向生成器写一个秒数。

**路线选择与取舍：** 将视频时间轴转换成 `cue_sheet`：每个事件有目标时间、容差、音乐动作、优先级和前后缓冲。需要严丝合缝时使用确定性剪辑和结构化编曲；模型只负责素材创作。

**落地 SOP：**

1. 解析视频镜头/字幕/旁白，生成对白避让时段与情绪转折点。
2. 先用短 clip 验证风格，再生成或编曲可拼接的音乐层。
3. 以精确采样点裁剪、crossfade、time-stretch 和循环材料实现分钟秒级配合。
4. 在最终视频混流后再次用音频时间线验证 cue 偏差；配乐必须与实际导出版本同检。

**验收与数据采集：** cue 时差毫秒、段落进出点通过率、旁白遮蔽投诉数、重新剪辑后返工耗时。

**残余风险与失败回退：** 一句“第 30 秒高潮”不能保证模型在目标点进入高潮；变速、压缩编码和视频帧对齐可能再引入偏移。

### MUS-017｜旋律/录音相似性检测与侵权判断混淆（P1）

**现有可行工具与证据：** 工程上可用音频 fingerprint 检测录音级重复、转 MIDI 的旋律序列检索、音频 embedding 做候选召回；这些工具主要回答“是否值得复核”，不能直接回答法律侵权。美国版权局的创作贡献规则也不把简单相似度作为侵权裁决标准 [S13]。

**路线选择与取舍：** 建立两级相似性风控：第一层低成本近重复/高相似检索，第二层音乐专家和法律审核；分离“已有录音素材重用”“常见和声套路”“旋律显著相似”和“声音身份模仿”四种类别。

**落地 SOP：**

1. 维护授权样本索引和保留敏感参考音频的访问权限。
2. 用音频哈希/指纹召回近重复，再按 4–16 小节旋律片段比较音高间隔与节奏轮廓。
3. 对高风险候选保留检索证据和人工判断，禁止自动裁定合法或违法。
4. 在分发前设置人工审查 Gate；收到权利通知时可追踪到具体输入素材、模型与发布版本。

**验收与数据采集：** 近重复召回率、误报率、人工复核工时、投诉处理闭环时间、未经授权引用阻断率。

**残余风险与失败回退：** 常用和弦、公共领域主题及风格相似可能导致误报；反过来经过变调/变速的采样也可能绕过简单 fingerprint。

### MUS-018｜音乐内容供给过剩、分发和真实受众不足（P1）

**现有可行工具与证据：** Deezer 2026-07 官方披露月均约 9 万首/日全 AI 新曲、峰值超过新增曲目的半数，但相关播放仅占 1%–3% [S01]；Spotify 2026-10 表示使用听众反馈、上传行为、元数据与 AI 检测识别垃圾内容，防止滥用推荐 [S02]。这些数据不能推成全行业播放分布。

**路线选择与取舍：** 以客户已确认的业务场景为入口，先做 B2B 定制 BGM、短剧视频、游戏音乐和品牌声音；不把流媒体垃圾曲目量产当作获客策略。根据实际完播、复听、授权购买与项目复购优化。

**落地 SOP：**

1. 确定可衡量的客户需求（精确时长、风格、授权、音轨格式），而非简单生成数量。
2. 每件作品按场景、关键词、情绪轨迹、音轨可用性及授权过滤建立检索。
3. 小批量 A/B 面向真实客户或合规受众测试，不做刷量、买量造假或重复上传。
4. 跟踪下载到项目采用的转化率、复购率和单客户服务毛利，不只看平台播放数。

**验收与数据采集：** 客户需求匹配率、真实采用率、复购率、授权收入/首、自然完整收听率、退货与投诉。

**残余风险与失败回退：** 公开平台发现机制会变；上传份额与收听份额口径不同。没有真实使用场景时，低成本大量生成也无法保证收益。

### MUS-019｜同质化与缺乏稳定原创风格身份（P2）

**现有可行工具与证据：** ACE-Step 1.5 提供 LoRA 数据准备、自动标签、训练和加载路径，可研究基于合法素材形成一致风格 [S27][S42]；但 LoRA 不保证作品可注册版权或不会近似训练素材。可编辑的 MIDI 动机、专属音色库与品牌声规范是更稳健的独特性来源。

**路线选择与取舍：** 先建设“可授权的品牌声音系统”：原创主题动机 8–16 小节、器乐模板、声线库、品牌音乐词典和禁用相似参考；仅在拥有合法数据及足够样本时试验 LoRA。

**落地 SOP：**

1. 与作曲/品牌方制定可审计的 style guide：情绪、和弦倾向、音色、节奏、主题动机和禁忌。
2. 数据集只纳入有明确训练许可与来源记录的音频；按作品和创作者分组进行 train/holdout 防止泄漏。
3. 在不同场景生成 10–20 个变体，检查辨识度、审美疲劳与音源/主题过拟合。
4. 把最终品牌识别测试交给客户和真实听众，而不是只依赖嵌入向量。

**验收与数据采集：** 品牌识别盲测准确率、风格一致性、人耳多样性、近重复警报率、素材许可覆盖率。

**残余风险与失败回退：** 对小数据集微调极易过拟合；引用特定现世音乐人的“风格”不等于拥有可用的录音/声线权利。

### MUS-020｜实时动态音乐的延迟、跨状态连贯性（P2）

**现有可行工具与证据：** Google Magenta RealTime 2 公开给出约 200ms 控制延迟、40ms 帧长等实验性能力，且支持 MIDI/音频/文本条件；这些属于官方模型说明而非端到端游戏交付 SLA [S43]。传统游戏音频中间件 Wwise 支持音乐段落、转换规则与过渡片段，能够先解决可预期的音乐切换 [S44]。

**路线选择与取舍：** 采用双路径：上线默认“预渲染分层音乐 + 小节/节拍同步的状态机切换”；需要实时即兴时增加生成式模型，做安全缓冲与回退。无缝音乐是节拍连续性问题，不只看毫秒延迟。

**落地 SOP：**

1. 定义游戏状态到音乐层的映射（探索、战斗、胜利、失败），预设 BPM/Key/拍号兼容范围。
2. 先在 Wwise/FMOD 类系统中实现与小节边界对齐的切换、过渡片段和循环。
3. 实时模型按音频线程与生成线程解耦，维持 ring buffer；发生 underrun 立即切换到预渲染音轨。
4. 监测输入动作到音频改变的延迟、爆音率、调性冲突率、循环缝与 CPU/GPU 开销。

**验收与数据采集：** P95 控制到可感知响应延迟、缓冲下溢次数/小时、跨状态和声违和评分、循环无缝成功率。

**残余风险与失败回退：** 实验室模型延迟不包含游戏引擎调度/音频 IO/网络波动；实时输出在风格长期一致性和版权条款方面仍需专门测试。

### 6.21 典型失败案例：单句歌词修订

**需求**：把 01:10—01:16 的歌词从 A 改为 B；除此之外伴奏、主唱声线和副歌力度不变。

**错误路径**：对整首音频重新提交一个修改后的歌词 Prompt → 生成一首听起来“差不多”的新曲 → 因为整体相似度高而误判通过。这样往往无法证明音轨和演唱保真。

**正确路径**：

1. 从原版 `master.wav` 派生新的编辑任务，保存 hash、时间段及目标字词。
2. 若有 MIDI 与 vocal stem：替换相关音符/歌词，合成新 vocal stem；伴奏逐比特复制。否则使用局部 inpainting 并明确保留区间。
3. 同步比较编辑前后 00:00—01:09 与 01:17—结尾，识别系统性声线/和声漂移。对压缩格式只作感知比较，不直接假设哈希会相同。
4. 人工听审边界、歌词和音色；只有目标编辑和保留都通过才进入下一阶段。
5. QAReport 记录 `edit_success=true/false` 和 `preservation_pass=true/false` 两个独立布尔值，报告失败样例音频位置。

### 6.22 典型失败案例：短剧 31 秒进入情绪高潮

**需求**：第 31 秒开始进入副歌/弦乐抬升，第 43 秒结束，不能压住旁白。

**错误路径**：给文本模型“31 秒进入高潮”，生成后直接输出视频。时间标签即使存在，也只是控制信号，不代表精确时间轴承诺 [S26]。

**正确路径**：按镜头帧/音频采样生成 `cue_sheet.json` → 用确定性节奏地图或分段片段编排 → 对片段进行受控伸缩与 crossfade → 混入对白 ducking → 最终视频出片后再次分析出入点。人工审听重要情绪时点和对白可懂度。

### 6.26 可运行的最低音频技术检查（示意）

```bash
# 先验文件是否可解码、获得时长/采样率/声道等信息
ffprobe -v error -show_entries   format=duration,format_name:stream=codec_name,sample_rate,channels   -of json output.wav

# 通过 FFmpeg loudnorm 输出音频响度/峰值分析信息
# 此处仅测量，不自动将任何平台都压到统一 -14 LUFS
ffmpeg -hide_banner -i output.wav   -af loudnorm=I=-16:TP=-1.5:LRA=11:print_format=json   -f null -

# 扫描长音频静音区间，是否异常需结合曲目结构判断
ffmpeg -hide_banner -i output.wav   -af silencedetect=noise=-50dB:d=2 -f null -
```

上述命令仅是可行的基础体检，不证明歌词准确、无版权风险或艺术性达标。`loudnorm` 的 I/TP 参数为滤镜分析设置，不能视作所有渠道的统一推荐目标。正式工程应检查 stderr、退出码、文件时长以及转码可能带来的测量偏差。

### 6.27 30 天优先建设的四个可交付模块

1. **music-quality-benchmark**：50 个统一 Brief、至少两条模型路径、独立的人声/结构/编辑保留测试、人工听评界面；输出可比较的错误率和可信区间。
2. **music-editing-gateway**：`edit_spec` 与 Provider region-edit/MIDI/stem 编辑路由；支持原版恢复、边界对比和版本图。
3. **audio-qa**：ffprobe/FFmpeg + 节拍偏移 + 质量 Rubric；每个失败关联最短时间窗口与责任模块。
4. **rights-release-gate**：模型许可证、输入音频、声线、发行渠道、AI 声明 5 类证据；任何 UNKNOWN 不得无人值守商用发布。

**阶段完成标准**：不要求生成模型本身变强，而要求每个已定义的失败都能被识别、定位、记录、转交对应修复路径，并且可以证明最终为什么允许或阻断发布。


## 7. 现有解决方案：哪类技术解决哪类问题

| 故障类型 | 优先策略 | 次级策略 | 不宜误用 |
|---|---|---|---|
| 改歌词改坏全曲 | 乐谱/MIDI + 人声重合成；局部 stems 改写 | 局部 inpainting + 保留测试 | 直接整曲重新生成后声称“无损编辑” |
| 结构漂移 | 小节/段落规划、主题重复约束 | 分段生成 + 桥接 | 仅增加风格形容词 |
| 错字和咬字 | 音素对齐、中文审听、真人补录 | ASR 风险筛查 | 把普通 ASR 的 CER 当唯一真值 |
| 乐器串音 | 原生 stems/MIDI 输出 | HTDemucs/MDX 等分离 + 人工修复 | 认为分离结果与原工程完全等价 |
| 节拍漂移 | DAW 节拍网格、onset/beat 校验 | 局部 time stretch | 任意整段拉伸而不试听 |
| 声音糊与嘶裂 | 查明生成/混音阶段并返工 | EQ、去齿音、动态控制 | 只靠母带掩盖生成伪影 |
| 质量模型误判 | 七维评分 + 专家盲听 | 任务专用诊断模型 | 单一 FAD/CLAP 的“总分” |
| 版权证据缺失 | 权利台账和人工审核 | 相似性检测辅助 | 让模型“保证无版权风险” |
| 平台导出限制 | Provider 多路由及许可快照 | 更换可导出服务 | 使用违反平台限制的抓取方法 |
| 批量发行被拒 | 按目的地制定发布策略 | 人工合规复核 | 未经验证的大规模重复上传 |

  ├── Hosted Model API
  ├── Local Open Model

        │

        │
        ├── FAIL ──► Diagnostic Report ──► Localized Revision Planner
        │                                      └────► Regeneration
        ▼

### 8.1 必须拆开的数据契约

- **MusicBrief**：受众、场景、情绪、用途、禁止事项。
- **SongSpec**：BPM、调性、拍号、结构、小节级 cue、语言、唱法、乐器、音轨和交付物。
- **GenerationManifest**：provider、model ID / version、提示词、seed（若可用）、配额/费用、输入引用、生成时间、失败日志。
- **AssetManifest**：音频 hash、采样率、声道、时长、stems 和 MIDI 清单、父版本。
- **QAReport**：技术故障、歌词错误、时序偏差、听审评分、定位时间段和纠正动作。
- **RightsLedger**：输入/声线/平台/输出权限与证据，发布目的地及生效日期。
- **ReleasePackage**：WAV、MP3、伴奏、独立音轨（若合法且可得）、封面、歌词、元数据、发布审核状态。

### 8.2 自动化 QA 四层门禁

**L0：合法产物与文件健康**：API 返回成功、内容能下载、授权可用、音频可解码、元数据完整；失败即停止。

**L1：信号与节拍指标**：时长、采样率、峰值、True Peak、静音异常、clipping、音轨延迟、拍点与结构；基于场景阈值判定。

**L2：音乐与歌词指标**：声线一致性、歌词可懂度、节奏/调性偏差、目标乐器、段落完整性、编辑保真；自动分数只作为筛查器。

**L3：人类创作与权利审核**：专业审听、场景适配、原创度风险、版权/声线凭证、客户批准。**L3 不应由自动评分替代。**

## 9. 评估基准设计：如何真正测量“最常见”的故障

### 9.1 数据集设计（建议工程基线，不是已实测结果）

- **50 个 Brief**：5 类任务（流行歌/抒情/电子/游戏循环 BGM/视频配乐）× 2 语言（中文/英文）× 5 种需求复杂度。
- **每模型 3 个随机尝试**：合计每个模型约 150 次生成。要跨模型比较，保持 Brief、预算和采样设置尽可能公平。
- **编辑测试集**：挑选 30 个样本，每个样本进行歌词、音符、配器、局部节拍、整段转场 5 类编辑，**分别测编辑成功与未修改区域保留**。
- **来源与合规测试**：每个 Provider 做 5 项最小矩阵：商业可用、下载可用、stems 导出、训练数据声明、发行渠道可用；有未知即标未知。
- **听评设计**：至少 3 位不同角色听评者，在不告知模型名称的条件下评分；报告评分分歧，不作伪精度排名。

### 9.2 核心度量与计算方式

| 指标 | 定义 | 注意事项 |
|---|---|---|
| `usable_yield` | 可交付作品数 / 总候选数 | 比“生成成功率”更贴近商业价值 |
| `first_pass_acceptance` | 不需返工即通过全部验收的数量 / 已评估数量 | 同时显示各 Gate 失败分布 |
| `edit_success` | 成功满足明确编辑要求 / 编辑任务数 | 与保存未修改内容分开 |
| `preservation_pass` | 人耳/目标检测确认编辑窗外未出现不可接受变化 / 编辑任务数 | 禁止单看波形差值；音频压缩会引入无关差异 |
| `lyric_intelligibility` | 人工逐句正确识别比例与辅助 CER/PER | ASR 非真值，需要母语听评 |
| `cue_timing_error_ms` | 目标 cue 时点与成品事件时点的绝对差 | 对固定视频片段特别重要 |
| `stem_bleed_rating` | 漏入非目标音源的主观评分 + 客观量化 | 优先原生 stems，区分 bleed 和 fullness |
| `rights_complete_rate` | 具备用途所需全部权利证据的成品比例 | 证据不全不等于一定侵权，但不能自动批准 |
| `cost_per_accepted` | 全部生成/返工/审核/计算成本 ÷ 合格数量 | 需包含人力和失败重试 |
| `provider_failure_rate` | 超时、配额、下载失败、不可解析输出数量 / 请求数 | 与“歌曲质量失败”分离 |

### 9.3 建议初始验收门槛（仅供第一轮实测校准）

- 文件能解码、发布必需的 RightsLedger 字段完整：**100%**（发布阻断条件）。
- 不能出现无法解释的音频中断、削波或不合规格式；允许审核员批准有意设计的失真效果。
- 固定画面配乐的 `cue_timing_error_ms` **先把 100ms 作为人工抽检报警线**；不同镜头和节奏场景可调整，不能当行业统一标准。
- `first_pass_acceptance`、`preservation_pass` **先测基线，暂不承诺行业基准阈值**；每轮迭代争取改善并附统计置信区间。
- 任何声线授权、外部采样授权缺失的商业作品：发布 Gate 直接 BLOCK。

## 10. 成本模型：不能只算生成一次的价格

`C_accepted = (C_generation + C_regeneration + C_separation + C_review + C_compute + C_licensing + C_delivery) / N_accepted`

其中 `N_accepted` 是经内容与权利双重验收的合格作品数。增加候选数量可能降低挑选难度，但若引起人工听审、分轨修复和发行审查成本上升，总成本未必下降。

需要特别监控：

1. 每首合格作品的候选数与返工次数。
2. 最高耗时的失败类型及是否可局部返工。
3. 人工听审与专业混音的时间成本。
4. 模型下载、并发配额变化对任务完成率的影响。
5. 完成生成、可下载、可交付、可发行四种成功率的差异。

## 11. 按场景取舍：不应使用一套通用模型指标

| 场景 | 第一优先事项 | 第二优先事项 | 最可能阻断交付的问题 |
|---|---|---|---|
| 中文流行单曲 | 歌词准确、人声表现、结构发展 | 演唱风格与混音 | 歌词错/声线不稳/权利链 |
| 短剧 / 影视 BGM | cue 时间点、情绪弧线、对白避让 | 纯伴奏/多时长输出 | 时间锚点不准、不能做细微修改 |
| 游戏动态配乐 | 循环无缝、分层切换、节奏同步 | 主题一致性 | 实时响应与跨状态突变 |
| 广告品牌音乐 | 授权凭证、准确时长、品牌识别 | 快速版本迭代 | 未授权参考声线/客户验收失败 |
| 创作者背景音乐库 | 资产检索、稳定交付、许可结构 | 成本和批量 QA | 同质化、渠道策略、分离伪影 |
| AI 虚拟歌手 | 身份/声线一致性、原创表达 | 可持续人设 | 声线权益与长期运营 |

## 13. 90 天实施计划与客观验收

### 第 1—15 天：建立 Issue Inventory 与真实基线

- 完成 50 个 Brief、标准化生成参数、权利字段定义。
- 实装音频解析、长度、峰值、静音、节拍估算和人工评价录入。
- 比较至少两条互不依赖的可导出生产路线；建立 Provider 能力快照。
- **退出条件**：能够复现 P0 失败并按症状生成 Issue，而不是仅输出“质量不好”。

### 第 16—30 天：P0-001 / 002 / 003 / 004

- 开展按段落的结构规划；将硬音乐约束移至符号/工程层。
- 建立中文歌词对齐、人声质量评价、修改保真测试。
- 产出编辑案例库，保留失败及成功样本。
- **退出条件**：编辑成功率与内容保留率能被独立统计，并形成可重放对比。

### 第 31—45 天：P0-005 / 006 / 007 / 008

- 七维听评与机器诊断并行；权利台账和导出/发行阻断 Gate 上线。
- 对 Bandcamp/TuneCore/DistroKid/YouTube 等渠道设不同准入策略。
- **退出条件**：没有权利凭证的作品无法通过自动发布，且每个拒绝都有可读原因。

### 第 46—60 天：P1-009 / 010 / 011 / 012

- 多轨质量评估、节拍偏移诊断、分轨误差审听、中文纠错。
- 从“整首重做”转向“识别最小返工单位”。
- **退出条件**：指定缺陷可定位到时间窗口或音轨，返工前后可比较。

### 第 61—75 天：P1-013 / 014 / 015

- Provider 路由、幂等重试、显存调度、成本日志、资产版本图。
- 进行 API 限流、下载取消、超时、OOM 的故障注入演练。
- **退出条件**：单 Provider 故障不会丢失已生成资产，失败任务可恢复或降级。

### 第 76—90 天：P1-016 / 017 / 018 + 交付验收

- 以短视频/短剧场景完成端到端项目：cue sheet → 音频 → 时序校验 → 人工审核 → 权利包 → 客户交付。
- 计算合格率、返工成本、审核工时和真实客户满意度。
- **退出条件**：不以生成次数，而以可验收交付物、权利完整性和实际客户反馈评估成果。

## 14. 决策建议

1. **研发首位：局部编辑保真与独立评估。** 专攻 “改需要改的部分，同时不改变不需要改的部分”。
2. **交付首位：权利、文件与渠道策略门禁。** 任何无法合法导出和发布的路径都不能成为生产系统的单点依赖。
3. **音质首位：原生 stems/MIDI 优先。** 将后处理分离视作补救，不能代替音乐工程素材。
4. **商业首位：先做有精确需求的 B2B 场景。** 如短剧配乐、游戏音频、广告定制；避免把“海量上传”当作规模化成功。
5. **平台路线：自有任务契约 + 多 Provider + 可替换资产存储。** 把模型能力视作可切换组件，把音乐资产、审核证据和客户关系留在自己的系统中。

## 15. 未解决的研究问题

- 对不同模型，编辑窗口外的人耳感知变化是否能用可解释指标稳定预测？
- 有无比“文本 Prompt + 重采样”更好的结构化编曲控制接口？
- 真实中文听众对咬字、唱腔和声线一致性的容忍阈值分别是多少？
- 如何避免分轨之后的微小相位问题在混音中放大？
- 对真正授权模型的发行准入，各分销商实际可接受的证明材料是什么？
- “使用了 AI”与“人类实质性创作”在不同市场的实务分界如何变化？
- AI 生成音乐的真实商业购买率、收藏率和复听率是否存在跨平台可比数据？
